## 🔐 Privacy & Security Rules

> **CRITICAL**: The Private folder contains personally identifiable information (email addresses, phone numbers, member registration data).

### Agent Privacy Requirements

**Always verify folder context before any file operation:**

✅ **Safe Operations**:
- Read any file for analysis
- Create/edit README.md files
- Organize files within appropriate folders
- Suggest content changes to user

❌ **Prohibited Operations**:
- Never copy Private folder contents to Public
- Never include PII in public-facing documentation
- Never suggest exposing member contact data
- Never create public files containing email addresses or phone numbers

### Before Every Write Operation

```
IF target_path contains "/Private/" AND operation is copy/move:
    IF destination_path contains "/Public/":
        REJECT - Privacy violation
    ELSE:
        Verify no PII in content
```

## 📝 File Naming Convention

**Standard Format**: `YYYY-MM-DD_Description.ext`

**Examples**:
```
✅ 2024-01-15_Board_Meeting_Minutes.docx
✅ 2023-12-Newsletter.pdf
✅ 2024-Q1_Financial_Report.xlsx

❌ meeting notes.docx
❌ 1-15-24-minutes.docx
❌ Board Meeting Jan 15.docx
```

**When Renaming Files**:
1. Extract or infer the date from content/filename
2. Create descriptive name following convention
3. Preserve file extension
4. Suggest rename to user (don't auto-rename without approval)

## 🔧 Google Drive File Types

### Understanding Google Workspace References

**What are `.gdoc`, `.gsheet`, `.gslides` files?**

These are **reference files** created by Google Drive sync, not actual documents. They're small JSON files (~173 bytes) containing:
```json
{
  "doc_id": "1mY9B58rTVYk5oSrbjEWpvEXiNICzjwqCF682_YBLn9g",
  "email": "gabeduke@gmail.com",
  "": "WARNING! DO NOT EDIT THIS FILE! ANY CHANGES MADE WILL BE LOST!"
}
```

### Agent Capabilities with Google Workspace Files

**✅ CAN DO**:
- Read reference files to extract document IDs
- Generate web links: `https://docs.google.com/document/d/[DOC_ID]`
- Describe what the file references
- Create markdown files that link to Google Docs

**❌ CANNOT DO**:
- Edit Google Doc/Sheet content via filesystem
- Create new Google Workspace files directly
- Modify document permissions

### Working with Google Workspace Files

**To reference a Google Doc in documentation**:

```python
# 1. Read the reference file
content = read_file("path/to/file.gdoc")
doc_data = json.loads(content.split('\n')[0])
doc_id = doc_data["doc_id"]

# 2. Create link
link = f"https://docs.google.com/document/d/{doc_id}"

# 3. Include in markdown
markdown = f"[Document Name]({link})"
```

**To suggest edits to Google Workspace content**:
```
"The Google Doc 'Meeting Minutes' contains [issue]. 
To fix this, please:
1. Open: https://docs.google.com/document/d/[DOC_ID]
2. [Specific edit instructions]"
```

## 🚨 Troubleshooting

### "Cannot edit Google Doc"
**Solution**: This is expected. Google Docs must be edited in browser.
- Extract doc ID from `.gdoc` file
- Provide link: `https://docs.google.com/document/d/[DOC_ID]`
- Suggest specific edits for user to make

### "File not syncing"
**Solution**: Google Drive sync issue, not agent issue.
- Check if file exists in filesystem
- Suggest user check Google Drive sync status
- Recommend opening Google Drive web interface

### "Privacy concern about file operation"
**Solution**: 
- Stop operation immediately
- Explain privacy violation
- Suggest alternative approach
- Never proceed without user confirmation

## 📚 Best Practices

1. **Always read READMEs first** before making changes to a folder
2. **Verify dates** when renaming files to standard format
3. **Preserve context** - don't delete files without user approval
4. **Document changes** - update READMEs when folder structure changes
5. **Privacy first** - when in doubt, ask user about PII
6. **Suggest, don't assume** - get approval for major reorganizations
7. **Link, don't copy** - reference Google Docs by URL, not content
